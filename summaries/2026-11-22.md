#### OpenAI News
**Inside the Codex sandbox**  
**核心论点**：Codex 采用「纵深防御」策略，在用户原机环境利用操作系统原生沙箱机制（macOS Seatbelt、Linux Landlock、Windows AppContainer）对 Agent 执行的命令实施细粒度文件系统与网络访问控制，而非依赖容器/虚拟机隔离。  
**关键要点**：
- 默认权限画像 `:workspace`：工作区可写、`.git/.codex` 只读、广泛读取（受 OS 权限限制）、禁用网络；在保证常见编译/构建工具链可用与防止数据外泄之间取得平衡。  
- 沙箱通过 `spawn_command_under_sandbox()` 统一 API 启动进程，子进程自动继承父进程约束，形成完整进程树隔离。  
- 用户可在 `config.toml` 自定义画像，支持 `read`/`write`/`deny` 三种文件系统规则与网络代理配置，企业可结合 Codex Security Cookbook 落地合规策略。  
- 设计权衡：不进容器避免了 iOS 模拟器、原生工具链无法在沙箱内运行的问题，但需在三大平台分别投入大量工程适配原生沙箱 API。  
- 仍存在攻击面：如向 `node_modules` 注入恶意代码利用编辑器自动格式化触发，因此必须结合模型对齐与训练形成纵深防御。  
**值不值得深读**：值得。这是目前公开最详尽的「在宿主机安全运行代码 Agent」的工程实现细节，对任何做本地/桌面端 Agent 的团队极具参考价值。  
**原文链接**：https://openai.com/index/inside-the-codex-sandbox

#### Hugging Face Blog
**XYBench: Helping with the problem behind the question**  
**核心论点**：发布 XYBench（8115 真实样本），系统性评测大模型识别并纠正用户「XY Problem」（问错问题）的能力；实验显示所有主流模型倾向「答着问的问题」而非「解决真实目标」，即使给出真实意图也难稳定修正，揭示了「实用性」与「基准分」的巨大鸿沟。  
**关键要点**：
- 样本来源：Stack Overflow 1557、Stack Exchange 184、人工 102、WikiHow 生成 6272；每题标注显性请求 Y 与隐性目标 X。  
- 三维评测：Pragmatic solution（是否给 X/Y 方案）、Pragmatic emphasis（侧重 X 还是 Y）、Misconception identification（是否引导远离 Y 走向 X）。  
- 结果：Stack Overflow 上模型给 Y 方案 75–86%，给 X 方案仅 59–71%；侧重 X 的仅 35–41%，侧重 Y 的 47–57%。  
- Oracle 实验给出真实意图 X：Sonnet 4.6 给 X 方案率 59%→67%，但误解识别率反降 47%→34%，说明「知意图」≠「能按意图答」。  
- 判别 vs 生成差距：同模型做选择题时 71–84% 选以 X 为主的答案，自己写时仅 35–41% 以 X 为主。  
- 人类参考答案在所有指标上显著领先，模型仍无法像专家一样「先诊断再开方」。  
**值不值得深读**：值得。为「评测 AI 助手实用性而非知识量」提供了标准化工具与基准数据。  
**原文链接**：https://huggingface.co/blog/allenai/xybench

**The Definitive Fine-Tuning Guide for 3D Generation Models**  
**核心论点**：提供 TRELLIS.2（统一隐式表示的 3D 生成模型）LoRA 微调全流程：仅对稀疏结构流 DiT 与形状流 DiT 加 LoRA（共 930 万可训练参数），冻结纹理流 DiT 避免灾难性遗忘；配套预处理/训练 Docker 镜像可在 HF Jobs 或本地 GPU 运行。  
**关键要点**：
- TRELLIS.2 五阶段：去背景→DINOv3 编码→稀疏结构流（16³ latent）→形状流（512³ O-Voxel 几何）→纹理流（材质）→导出 GLB。  
- 实验用 GSO 188 双鞋数据，预训练模型鞋底几何不准，LoRA 微调后显著改善。  
- 纹理流需分离材质贴图（base color/metallic/roughness/alpha），GSO 仅有烘焙光照的 diffuse map，强行微调会把光照学成材质属性。  
- 小数据集（<200 样本）LoRA 优于全量微调：成本低、保留先验、约 930 万 adapter 参数（结构流 rank 8、形状流 rank 16）。  
- 提供完整容器化脚本、超参解释、数据转换流程，降低 3D 微调门槛。  
**值不值得深读**：若关注 3D 生成落地或 LoRA 实战，极值得；否则可略读架构设计思路。
