**Redesigning source control at Anthropic**  
**核心论点**：AI 编码使日合并量从 2.5k 飙至 30k+，Git 为离线分布式设计的架构成为瓶颈，Anthropic 自研中心化、客户端极轻、API 优先、水平可扩展的 Scion 版控系统并完成五个月全量迁移。  
**关键要点**：
- 单主分支历史近 100 GB、压缩工作副本超 25 GB、每日 2500 万次 CI checkout、若走 Git 协议需 600 PB/天流量  
- 设计原则：客户端始终在线、客户端-服务端极度不对称（服务端承担历史/归并/变基、客户端仅缓存与工作区）、所有源控查询暴露 API 供 CI/工具直调、全组件水平扩展无全量副本、提交/变基/合并增量计算与仓库规模无关、工作副本可选且稀疏/虚拟化  
- 核心数据结构：changeset（写前日志条目）替代 Git commit，存文件级变更列表而非树指针，便于增量索引  
- 服务端由独立可扩展微服务组成：变更存储、文件索引、合并引擎、权限、通知等  
- 客户端协议基于 gRPC，支持稀疏/虚拟化 checkout、按需物化文件、乐观并发控制解决冲突  
- 迁移策略：双写期并行运行、历史只读归档、增量切流量、工具链（Antique code review、代码搜索、IAM）同步重写  
- 成果：CI checkout 延迟从分钟级降至秒级、镜像集群从数百台缩至零、开发者体验统一（CLI、IDE、Web 均调用同一 API）  
**值不值得深读**：**值得**——极少见的「AI 编码反哺基建」实战复盘，架构决策可迁移至任何高并发单体仓库场景。  
**链接**：https://www.anthropic.com/research/redesigning-source-control
